# InvoiceLens recovery matrix

Updated 1 November 2026. Decision is authoritative for registrations, evaluations, reservations, final review state and PO commitments. Workflow is authoritative for uploaded document bytes, reviewer history and durable jobs. Extraction owns cached extraction responses, keyed by document hash and extraction operation ID. Cross-service HTTP responses are never treated as durable evidence by themselves; callers retry their stable operation ID and receivers persist the request fingerprint and response.

| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Crash before a downstream request is sent            | Caller’s durable Workflow job and operation key                                                          | Expired lease requeues the same job; send the same generation-specific key when the worker restarts. Do not mint a new operation for a retry.                                                                                                                                                                       | E2E marks a newly queued job running with an expired lease before its first Decision registration, verifies Decision has no record, restarts Workflow, and confirms completion.                |
| Receiving service commits but response is lost       | Receiver’s transaction and `decision_operations` (or Extraction cache)                                   | Replay the exact request and idempotency key. A different request under the same key is rejected. Decision review and commitment changes commit in one transaction.                                                                                                                                                 | Lost Decision approval response, retried review, and one-commitment assertion pass in E2E.                                                                                                     |
| Caller crashes before recording success              | Receiver record plus caller’s still-running/failed durable job                                           | Recover the expired lease or use the supported retry action. The replay returns the committed response; Workflow final state, review reason, stage/job state and event are committed together.                                                                                                                      | Restart, lost-response review replay, persisted reason and one commitment pass in E2E. Stage/evaluation/failure events share the local Workflow transaction with their state transition.       |
| Duplicate retries                                    | Stable operation key and receiver request fingerprint; unique invoice/commitment constraints             | Identical retry replays. A changed payload is a conflict. Registration, evaluation, review and reference-import operations are idempotent.                                                                                                                                                                          | Registration/evaluation fence replay and review replay are exercised; stale-generation replay regression added.                                                                                |
| Expired processing lease                             | Workflow `workflow_jobs` lease, attempts and invoice generation                                          | Worker reclaims expired leases; stale lease tokens cannot write. Repeated failures stop at the retry cap and require an operator retry after service checks.                                                                                                                                                        | Expired lease recovered after Workflow restart in E2E. Exhaustion at the retry cap is not fault-injected.                                                                                      |
| Evaluation finishes after a newer invoice correction | Workflow invoice generation and Decision `decision_records.generation`                                   | Before accepting a correction, Workflow advances Decision’s monotonic generation fence using a durable idempotency key. The fence clears only a pending obsolete evaluation, reservation and business claim. Decision rejects a new stale evaluation; Workflow’s lease/generation guard rejects stale local writes. | Isolated test fences generation 2, attempts a late generation 1 evaluation, replays the old evaluation key, evaluates corrected inputs, and verifies one reservation for the corrected amount. |
| Concurrent correction and approval                   | Workflow invoice row lock and status/generation; Decision row lock, expected generation and final review | The first request to lock and queue the invoice advances its generation/status. The competing request sees queued/running or a generation mismatch and receives 409. Decision independently checks the expected evaluation generation before committing money.                                                      | Correction-versus-approval race is exercised in the isolated E2E harness; whichever request wins must leave one matching reservation/approval and no stale approval.                           |

A restart preserves it. Repair copies only the authoritative Decision final state and audit operation ID; it never changes commitments. Repeated repair is a no-op.                                                                                                                      | E2E restarts the isolated Workflow service after scan and before repair, then checks one commitment after repair and replay.                                                                   |

## Current automation boundary

Reconciliation automatically repairs the consequential case where Decision has committed an approval/rejection and Workflow still shows pending. The generation fence prevents stale evaluation results from being committed after Workflow accepts a correction. The administrator scan does not yet automatically repair every other discrepancy (for example, a missing registration, document/hash mismatch, or unexplained reservation); investigate those cases against both service databases and the private document manifest. Never manually create, release, or duplicate a commitment to resolve a timeout. Preserve request keys, invoice ID, generation, correlation ID and both service records when escalating.

If a retry reaches the maximum lease attempts, verify readiness, service logs and database connectivity before using the existing retry control. Do not correct or approve while a workflow job is queued or running. For an uncertain review response, retry its failed review job so it replays the same Decision operation key; do not submit a new approval command.
